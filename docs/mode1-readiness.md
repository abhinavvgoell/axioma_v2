## Gate 1 exit criteria

Do not start Mode 2 until all of these are supported by artifacts and recorded commands:

1. **Met locally:** Python and Java submissions completed in Docker for function and stdin/stdout paths.
2. **Met locally:** all 6 Docker-backed abuse checks passed on Docker Desktop's Linux-container runtime; none were skipped.
3. **Not met:** the previous complexity evaluation has 49 scorable cases, below the evaluator's 50-solution indicator; its held-out examples have already informed analysis changes and are no longer an untouched holdout. A separate 30-case calibration candidate set is ready, but only cases 001–005 have owner-confirmed labels. Review cases 006–030, freeze the complete calibration labels before analysis, and select a new untouched holdout after tuning.
4. **Met locally, smoke set only:** one correct control and three source-reviewed mutants were labeled before Axioma checks; the report records 3/3 detected mutants, 0/1 flagged correct controls, denominators, and wide Wilson intervals. Broader problem and fault coverage remains necessary for general claims.
5. **Met locally, narrow scope:** two Python candidates were preselected, passed all configured equivalence checks, and have paired counts at four increasing sizes with preselection manifests and raw source reports. The measurements are line/opcode work counts, not wall-clock speedup.
6. **Met locally, with a limitation:** a clean run of 20 sequential Python jobs in a fresh PostgreSQL database completed with valid timing in all 20 cases. The report is Python-only, small, and host-specific; it is descriptive and does not establish a public service SLO.
7. **Met for the current hosted CI workflow:** all three GitHub Actions jobs pass for commit `f94bf53` (Python API/worker/evaluators, Docker/Java harness, and frontend lint/build). This does not verify deployment or complete the independent complexity-evaluation gate.
8. **Met locally:** the user approved the analyzer UI on 2026-10-22. Their separate final frontend designs may still inform future UI work.

The current repository has working implementation paths and reproducible evaluator tools, but Gate 1 is not complete. The first human-reviewed complexity evaluation found 49 scorable samples, with 33.3% exact accuracy on the held-out partition; those examples have since informed analysis changes and cannot serve as a fresh holdout. The new broad calibration candidate set has 30 source-verified cases, with owner confirmation recorded for 5/30; the remaining 25 labels must be reviewed before the set can be frozen and analyzed. A separate 28-case BFS v2 run initially had 82.1% response agreement and estimates for 3/28 cases; after targeted development changes, a replay on that same packet reached 28/28 response agreement and exact estimates on 8/8 emitted cases. Both BFS results are targeted development diagnostics, not final holdout evidence; see the [original report](../evaluation/mode1/bfs-fresh-v2-results-2026-10-30/evaluation-report-v2.md) and [post-change development report](../evaluation/mode1/bfs-fresh-v2-development-2026-10-30-run-02/development-report-v2.md). Detection and optimization evidence remain narrow local smoke evaluations and must not be generalized. The controlled 20-job latency sample is too small and narrow to establish a public service SLO. The evaluator's 50-solution indicator is only a count check; it cannot verify label quality or independence.
